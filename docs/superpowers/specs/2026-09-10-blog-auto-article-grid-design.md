# JOTO Global Blog 自动文章主网格集成设计

## 目标

修复 `jotoglobal.com` 三语 Blog 列表的自动文章展示与语言标记：彻底下架当前 12 篇不符合要求的自动文章；未来新发布文章应进入现有 Blog 主网格顶部，沿用当前深色卡片视觉，并按发布时间从新到旧排列；页脚之后不得再出现任何文章模块。

## 当前问题

- 发布集成器在三语 Blog 页面 `</body>` 前插入独立的 `#jotoglobalArticles` 区块。React 主站及页脚都位于 `#root` 内，因此该区块必然出现在页脚之后。
- 独立区块使用白色卡片 CSS，与现有深色 Blog 设计不一致。
- 发布器每次发布文章都会再次运行集成器，所以仅修改当前线上 HTML 无法永久解决问题。
- 三语 Blog 列表的静态 HTML 都使用 `lang="en"`，导致中文和波斯语页面的语义及自动文章语言判断错误。
- 发布器从上一版本复制文件后再渲染文章；如果只从数据索引中移除文章，旧详情目录仍可能残留。
- 通用 Nginx 路由会把不存在的 Blog 详情回退到 SPA 首页并返回 HTTP 200，造成不利于搜索引擎下架的软 404。

## 方案

### Blog 列表集成

- 集成器不再创建独立的 `<section id="jotoglobalArticles">`。
- 页面只加载自动文章脚本与必要样式。
- 自动文章脚本等待 React Blog 主网格出现，并将生成的文章卡片直接插入该网格顶部。
- 所有自动卡片使用 `data-joto-admin-article` 标记，脚本重复执行时先移除旧的自动卡片，保证幂等。
- 自动文章按 `publishedAt` 降序排列；现有 6 篇固定文章保持原顺序，位于自动文章之后。
- 数据请求失败、数据为空或未找到 Blog 主网格时，静默保留现有 6 篇文章，不影响主页面与页脚。

### 卡片数据与视觉

- `article-data/index.json` 为每篇文章输出 `heroImage.url` 及三语 `alt`，供列表卡片使用。
- 自动卡片采用与现有 Blog 卡片一致的深色背景、边框、三列响应式布局、图片比例、标题、摘要、日期和阅读入口。
- 分类使用本地化的通用标签：英文 `Enterprise IT`、中文 `企业 IT`、波斯语对应译文；不虚构文章未提供的具体分类。
- 不再使用原有白色 `.joto-article-card` 列表样式；文章详情页所需样式继续保留。

### 当前 12 篇文章下架

- 在修改线上数据前创建带时间戳的私有备份，备份不放入 Web 根目录。
- 从 JOTO Global 文章源数据中移除当前 12 篇文章。
- 新发布版本不生成这些文章的列表数据、详情页与 sitemap 条目。
- 构建新版本时根据上一版 manifest 清理已下架文章的旧详情目录，且只允许删除 manifest 中记录的 Blog 文章路径。
- Nginx 对三语 `/blog/` 路径只提供真实存在的静态文件；不存在的详情 URL 返回 HTTP 404，不再回退到 SPA。
- 通过原子切换发布新版本；验证失败时不切换。

### 多语言 HTML

- `/blog/` 使用 `<html lang="en">`。
- `/zh/blog/` 使用 `<html lang="zh-CN">`。
- `/fa/blog/` 使用 `<html lang="fa-IR" dir="rtl">`。
- 自动文章详情页继续由渲染器输出对应的 `lang` 与波斯语 `dir="rtl"`。

### 发布链路

- 后台发布器继续复制当前稳定版本、同步最新版发布工具、运行集成器与文章渲染器、执行验证，再原子切换 `current`。
- 更新服务器发布工具目录，确保后续自动文章发布使用修复后的集成器、脚本、样式、渲染器和验证器。
- 当前 12 篇下架与代码修复使用同一个新版本上线，避免出现中间状态。

## 验证标准

- 三语 Blog 页面各只有一个页脚，页脚是页面最后一个可见内容区。
- DOM 中不存在 `#jotoglobalArticles` 独立区块。
- 当前 12 篇文章的三语详情 URL（含有无尾斜杠）均返回 HTTP 404，且不出现在 `article-data/index.json`、manifest 和 sitemap 中。
- 使用测试文章构建时，自动文章出现在现有 6 篇之前，并按发布时间降序排列。
- 自动文章卡片在桌面端和移动端不破坏现有布局。
- 三语页面的 `document.documentElement.lang` 与路由一致，波斯语页面同时为 RTL。
- 集成器连续运行两次不会产生重复脚本、样式或卡片。
- 发布器相关单元测试、文章渲染测试、静态验证、`git diff --check` 和线上浏览器冒烟全部通过。

## 非目标

- 本次不重写压缩后的 React 主程序。
- 本次不调整自动文章生成主题、写作质量或审核流程。
- 本次不改动现有 6 篇固定文章的内容与顺序。
