# 移动端 Hero 动效与首屏布局设计

## 背景

移动端 Hero 目前直接渲染 HLS `<video>` 背景。在微信内置浏览器和部分 iOS 版本中，视频自动播放被拦截后，浏览器会在视频上显示原生播放按钮。同时，现有移动端 Hero 高度由内容决定，390 × 844 视口下高度约为 477px，导致“核心能力”在首次打开时已经露出。

## 目标

- 移动端保留背景动效，但不再使用可见的 `<video>`。
- 彻底消除微信和 iOS 可能叠加的原生播放按钮。
- Hero 至少占满一个移动端视口，首次打开时不显示“核心能力”。
- Hero 主内容比当前位置稍微下移，但标题、文案和两个按钮始终完整可见。
- 英文、中文和波斯语首页使用同一套响应式规则，并防止横向溢出。
- 桌面端继续使用现有视频背景。

## 视觉与动效

在 `max-width: 1023px` 下隐藏 Hero `<video>`，由 Hero 容器的伪元素提供动态背景：

1. 底层保留现有深黑绿色调。
2. 叠加两组模糊绿色光带，使用 `transform` 和 `opacity` 进行缓慢横向漂移与呼吸。
3. 动画仅修改合成属性，避免频繁布局和重绘。
4. 开启 `prefers-reduced-motion: reduce` 时停止位移，保留静态光带。

动效只是背景氛围，不覆盖内容层的点击区域，也不会接管滚动。

## 移动端布局

- Hero 和 Hero stage 使用 `min-height: 100svh`，并为不支持 `svh` 的旧浏览器保留 `100vh` 回退。
- 内容在除去顶部导航后的可用区域中视觉居中，并轻微向上偏移，避免底部留下过大空白。
- 普通手机中，内容位置比现有 `135px` 顶部位置更低；Hero 底部则不早于首屏底部。
- 短屏设备通过高度媒体查询减小上下留白和标题位移，优先保证 CTA 完整可见。
- 保留 `min-width: 0`、`max-width: 100%` 和页面横向裁切，防止 320px、375px、390px 和 430px 视口出现右侧突出。

## 技术边界

- 在现有 `assets/homepage-refinements.css` 中实现布局与动效。
- 如需稳定选中视频，在 `assets/homepage-refinements.js` 中为 Hero 视频添加用途明确的 data 属性；不修改编译产物的业务结构。
- 不改动桌面端 Hero 视频、文案、CTA 目标、后续板块内容或路由。

## 验收标准

- 中文、英文和波斯语首页在 320 × 568、375 × 667、390 × 844 和 430 × 932 视口下，Hero 内容与 CTA 完整可见。
- 上述视口初始加载时，`#solutions` 顶部不出现在可见区域内。
- 移动端 Hero 中的 `<video>` 不可见，页面不出现原生播放按钮。
- 移动端背景保持可见的缓慢动效；减少动效模式下为静态。
- `document.documentElement.scrollWidth === window.innerWidth`，无横向溢出。
- 桌面端视频背景仍然可见，按钮和后续页面功能无回归。
