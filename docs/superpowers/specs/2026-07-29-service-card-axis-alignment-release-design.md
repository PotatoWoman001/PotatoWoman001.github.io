# 首页服务卡中轴对齐与线上发布设计

## 目标

统一首页“全生命周期服务”六张卡片的视觉中轴：每张卡片的绿色图标与标题水平居中，并共享同一条垂直中轴；说明文字继续按当前语言的阅读方向起排。完成后生成独立静态资源版本，保留线上旧版本并发布至 `jotoglobal.com`。

## 已确认范围

- 英文、中文、波斯语首页的六张服务卡使用同一规则。
- 图标与标题居中；说明文字不居中。
- 不调整卡片网格、编号、背景、尺寸、文字内容或其他区块。
- 共享服务卡组件在解决方案分类页沿用相同的图标—标题中轴规则，避免同一组件出现两套对齐方式。
- 静态资源版本从 `20260728-6` 升级为 `20260729-1`，避免浏览器继续命中旧缓存。
- 线上发布使用新的版本目录并切换当前版本，不覆盖或删除历史版本。

## 方案比较

### 方案 A：共享增强样式覆盖（采用）

在 `homepage-refinements.css` 中拆分标题与说明文字规则：标题设置 `text-align: center` 和 `justify-content: center`，说明文字保留 `text-align: start`。优点是改动小、覆盖三语言和共享组件、回归风险最低。

### 方案 B：逐页修改 HTML 类名

直接改三个首页生成后的 HTML。优点是结果直观，缺点是重复代码多，后续集成脚本或重新导出页面时容易丢失。

### 方案 C：修改主压缩样式包

改动主构建产物。能够减少覆盖层，但可维护性差，容易误伤其他卡片与响应式规则。

## 实现边界

1. 静态合约先断言标题居中、正文起排，再修改 CSS 使测试通过。
2. 三语言桌面与手机视口均验证六张卡片数量、图标和标题中心点误差、正文对齐、横向溢出与控制台错误。
3. 运行现有站点、轮播、表单、导航、Logo 墙等回归脚本。
4. 提交精确改动，推送当前维护分支。
5. 基于提交构建不可变发布包；服务器创建新版本目录，保留旧目录，再原子切换当前版本。
6. 在线验证 HTTPS、资源版本、三语言页面和服务卡对齐，并在右侧浏览器保留线上中文服务区作为交付页面。

## 验收标准

- 三种语言的每个服务卡图标中心点与标题中心点水平误差不超过 2px。
- 标题计算样式为居中；说明文字保持 `start` 对齐。
- 1440×900 与 390×844 均无页面级横向溢出。
- 现有静态验证全部通过，浏览器控制台无错误。
- `https://jotoglobal.com/zh/` 返回成功并加载 `20260729-1` 资源。
- 服务器旧版本仍可恢复，新版本成为当前线上版本。
