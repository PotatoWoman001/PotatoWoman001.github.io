# Why JOTO 统计动效设计

## 目标

在不改变首页 Why JOTO 现有左右布局、文案、卡片尺寸和深色视觉体系的前提下，引入受 Qoria “Global impact” 板块启发的滚动统计动效。动效用于强化 `2010` 与 `5` 两项可量化信息，同时让“多厂商”“全生命周期”两项文字信息以一致但克制的方式进入视口。

## 已确认方案

- 保留 Why JOTO 左侧标题与说明、右侧四张卡片的现有结构。
- 数值卡片 `2010` 与 `5` 从 `0` 缓出递增到目标值。
- 文字卡片“多厂商”“全生命周期”使用轻微上移和遮罩揭示，不使用打字、字符扰动或逐字闪烁。
- 四张卡片按阅读顺序错峰进入。
- 整组动效每次页面完整刷新只播放一次；离开板块后再次滚回不重播。
- 不改变现有 hover、边框、背景色、圆角、卡片尺寸及文案内容。

## 参考动效结论

Qoria 参考板块在进入视口前将统计值显示为 `0`，进入后约延迟 `0.5s`，并在约 `1s` 内递增至目标值。JOTO 采用相同的“进入视口后计数”逻辑，但降低延迟和错峰幅度，以适配更紧凑的四卡布局并减少用户等待。

## 交互时序

1. `#about` 首次与视口相交，且可见比例达到约 `25%` 时启动。
2. 左侧 Why JOTO 文案沿用现有淡入上移动效。
3. 右侧四张卡片按 DOM 阅读顺序依次启动：
   - 桌面和平板：相邻卡片间隔 `100ms`。
   - 手机：相邻卡片间隔 `70ms`。
4. 每张卡片使用约 `550ms` 的淡入上移过渡。
5. `2010` 与 `5` 在各自卡片启动后进行约 `1000ms` 的缓出递增。
6. 两张文字卡片使用约 `450ms` 的遮罩上移揭示。
7. 动画完成后移除运行态，释放 `requestAnimationFrame`；再次滚入不重新启动。

## 数字呈现

- 数字在脚本增强成功前保持原始最终值，避免 JavaScript 失败时页面显示为 `0`。
- 脚本完成目标值读取并绑定观察器后，才将可动画数值切换为初始值 `0`。
- 计数使用缓出曲线，使前段变化明显、末段平稳收敛。
- 使用 `font-variant-numeric: tabular-nums`，防止递增过程中字符宽度变化造成视觉抖动。
- 英文和中文保持当前阿拉伯数字显示。
- 波斯语使用当前页面的本地化数字格式；内部目标值仍使用语言无关的数值数据。

## 文字揭示

- “多厂商”和“全生命周期”不拆成单字节点。
- 文字值外层增加运行态数据属性，通过 `clip-path` 与 `translateY` 完成整体揭示。
- 动画只作用于值，不改变说明标签位置，避免卡片内容整体跳动。

## 实现边界

### JavaScript

在 `assets/homepage-refinements.js` 中增加独立的 Why JOTO 动效增强单元：

- 定位 `#about [data-about-stats]` 与四个 `[data-about-stat-card]`。
- 读取 `[data-about-stat-value]` 的最终文本并标记数值卡片、文字卡片和目标值。
- 使用单个 `IntersectionObserver` 触发首次播放。
- 使用 `requestAnimationFrame` 执行数值递增；结束或页面卸载后不保留循环。
- 使用 section 级数据属性记录 `ready`、`running`、`complete` 状态。
- MutationObserver 的多次补偿调用必须幂等，不重复绑定观察器或重置数值。

### CSS

在 `assets/homepage-refinements.css` 中增加：

- 卡片错峰进入所需的初始态、运行态和完成态。
- 数值等宽字符规则。
- 文字值遮罩揭示规则。
- 手机端较短的错峰延迟。
- `prefers-reduced-motion: reduce` 下的静态最终态。

不修改构建产物主包，不重排 HTML，不引入第三方动画库。

## 降级与异常处理

- 不支持 `IntersectionObserver`：直接显示最终值与完成态。
- JavaScript 初始化失败：HTML 原始最终值仍可见。
- 页面在动画期间切换到后台：下一帧根据实际经过时间继续并直接收敛，不积累循环。
- DOM 结构不足四张卡片：不启动增强，保留原有页面表现。
- 重复执行增强函数：检测已设置的数据状态并直接返回。

## 无障碍

- 动态递增过程中不使用 `aria-live`，避免读屏软件连续朗读每个中间值。
- 可访问名称保持原始最终文案；动画只改变视觉文本。
- 开启“减少动态效果”时直接显示最终值，不执行位移、遮罩和递增。
- 动效不改变焦点顺序，不新增可交互控件。

## 响应式与 RTL

- 桌面、平板和手机均保持当前栅格断点。
- 手机单列卡片按页面阅读顺序逐张进入。
- 波斯语维持现有 RTL 排列；动画的轻微垂直位移不随文字方向翻转。
- 动效不得引起页面横向溢出或布局高度变化。

## 验证标准

### 静态验证

- 三语言首页均继续加载统一版本的 `homepage-refinements.css/js`。
- 脚本包含单实例观察器、数值目标解析、`requestAnimationFrame` 和完成态。
- 样式包含数值等宽、文字遮罩以及 reduced-motion 静态规则。

### 浏览器验证

覆盖英文、中文、波斯语的桌面与手机视口：

- 初次进入 Why JOTO 时 `2010` 与 `5` 从 `0` 递增并到达准确最终值。
- 四张卡片按阅读顺序错峰进入。
- 文字卡片完整显示，不发生逐字闪烁或断行异常。
- 滚离后再次进入不重播。
- 页面刷新后允许重新播放一次。
- reduced-motion 直接显示最终值。
- 控制台无错误、无警告，页面无横向溢出。

## 非目标

- 不把 Why JOTO 改造成 Qoria 的八格统计布局。
- 不新增未经确认的公司指标、图标或说明文案。
- 不修改 Why JOTO 的色彩、卡片尺寸、圆角或 hover 风格。
- 不让动画在每次滚动进入时反复播放。
