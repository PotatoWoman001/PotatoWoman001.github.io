# JOTO Global 全站字体规范、Mall 导航与首页细节优化设计

## 1. 设计目标

本设计统一 JOTO Global 全站正式页面的字体层级与拉丁字体，同时完成以下首页和全站导航优化：

1. 将当前分散的字号收敛为可复用、可验证的全站文字系统；
2. 所有普通英文和拉丁字符统一使用本地 `Poppins`；
3. 首页 Hero 的“查看解决方案”和“联系我们”保持完全相同的外部尺寸；
4. 全生命周期服务与项目案例卡片采用“外层居中、文字按语言起始方向对齐”的结构；
5. 加强核心能力板块的首次横向滑动提示；
6. 在所有正式页面和详情页的 Blog / 最新资讯后加入 Mall 导航；
7. 创建英文、中文和波斯语三个本地化 Mall 占位页。

设计采用用户确认的 B「平衡型统一」方向：缩小过大的展示标题、提高过小的辅助文字，同时保留 JOTO 现有的深色视觉、绿色品牌色和大尺度排版特征。

## 2. 现状盘点

### 2.1 当前字号

在 `1440px` 桌面视口检查英文、中文和波斯语首页，以及 About、Contact、Blog、文章、Solution 分类和厂商详情代表页面后，发现：

- 首页存在超过 18 种实际字号组合；
- 全站实际字号跨度约为 `7px` 至 `144px`；
- 首页 Hero 普通标题约为 `112px`；
- Solution 分类页主标题最高约为 `144px`；
- 文章页主标题约为 `109px`；
- 首页板块标题常见值约为 `75px` 至 `101px`；
- 部分卡片标签和详情页装饰文字只有 `7px` 至 `9px`。

字号层级数量过多，造成标题之间缺乏统一比例，辅助文字在高分辨率屏幕上可读性不足。

### 2.2 当前字体

当前本地字体文件已包含 `Poppins` 400、500、600、700、800 字重，真实浏览器检查确认这些字重均可用。

普通英文元素的计算字体目前以 `Poppins` 开头，但仍保留 `Inter` 后备规则。中文和波斯语页面中的拉丁字符也需要显式锁定为 `Poppins`，避免不同组件继续继承其他字体。

绿色斜衬体文字当前使用 `Instrument Serif`，属于保留的品牌例外。

### 2.3 当前卡片与动效

全生命周期服务和项目案例的图标、Logo 与文字外层容器在几何上已经接近同一中轴，但文字列宽度过大且缺少显式的最大宽度约束，导致左对齐文字的视觉重心偏向一侧。

核心能力板块已有一次性提示动效，但当前位移上限约 `120px`，且存在启动延迟，用户在正常滚动过程中可能无法明确感知。

## 4. 全站字体层级

### 4.1 断点

文字规范使用三档响应式尺寸：

- 桌面：`min-width: 1280px`；
- 平板：`768px` 至 `1279px`；
- 手机：`max-width: 767px`。

跨断点可通过 `clamp()` 平滑变化，但在三个验证视口中必须分别落在下表目标值附近，允许不超过 `1px` 的浏览器舍入误差。

### 4.2 五级标题

| Token | 桌面 | 平板 | 手机 | 行高 | 字重 | 用途 |
|---|---:|---:|---:|---:|---:|---|
| `--type-t0` | `96px` | `68px` | `48px` | `0.92` | `600` | 首页 Hero、Solution 分类展示标题 |
| `--type-t1` | `72px` | `56px` | `40px` | `1.00` | `500–600` | 文章、详情页主标题 |
| `--type-t2` | `56px` | `44px` | `34px` | `1.08` | `500` | 首页和详情页板块标题 |
| `--type-t3` | `28px` | `26px` | `22px` | `1.20` | `500–600` | 功能组、主要内容卡片标题 |
| `--type-t4` | `20px` | `20px` | `18px` | `1.30` | `500–600` | 普通卡片标题 |

### 4.3 五级正文与辅助文字

| Token | 桌面 | 平板 | 手机 | 行高 | 字重 | 用途 |
|---|---:|---:|---:|---:|---:|---|
| `--type-b1` | `18px` | `18px` | `17px` | `30/30/28px` | `400` | Hero 和板块引导正文 |
| `--type-b2` | `16px` | `16px` | `16px` | `28/28/27px` | `400` | 标准正文、文章正文 |
| `--type-b3` | `14px` | `14px` | `14px` | `22px` | `400–500` | 卡片说明、紧凑正文 |
| `--type-l1` | `12px` | `12px` | `12px` | `18px` | `600` | Eyebrow、表单标签、状态标签 |
| `--type-m1` | `11px` | `11px` | `11px` | `16px` | `400–600` | 编号、日期、阅读时间、辅助信息 |

正常可读文字不得小于 `11px`。纯装饰性图形内部的坐标、状态刻度或不可作为主要信息来源的动画数据可小于 `11px`，但必须具有其他可访问的文本来源。

### 4.4 导航与按钮文字

- 页头桌面导航：`14px / 500`；
- 移动菜单导航：`16px / 500`；
- 标准 CTA 和紧凑按钮：`14px / 600`；
- 轮播圆形按钮只显示图标，不增加可见文字；
- 表单输入文字：`14px / 400`；
- 表单占位符：`14px / 400`；
- 页脚主链接：`14px / 400–500`；
- 页脚版权和辅助说明：`12px / 20px`。

## 5. 字体家族规范

### 5.1 英文页面

除绿色斜衬体例外外，所有英文和拉丁字符使用：

```css
font-family: Poppins, sans-serif;
```

适用范围包括：

- 页头和移动菜单；
- Hero；
- 标题、正文和标签；
- 按钮；
- 表单；
- 卡片；
- Blog 和文章；
- Solution 分类与厂商详情；
- 页脚；
- Mall。

普通英文元素不得最终继承 `Inter`、`Plus Jakarta Sans`、等宽字体或系统默认无衬线字体。

### 5.2 中文页面

中文页面使用：

```css
font-family:
  Poppins,
  "PingFang SC",
  "Microsoft YaHei",
  sans-serif;
```

浏览器会使用中文字体显示汉字，但以下拉丁内容优先由 `Poppins` 显示：

- `IT`；
- `JOTO`、`JOTO TECH`；
- `AI`、`SOC`、`SLA`、`SD-WAN` 等缩写；
- 产品名、厂商名；
- 英文按钮或标签；
- 数字、年份、型号和邮箱。

### 5.3 波斯语页面

波斯语页面使用：

```css
font-family: Poppins, Vazirmatn, sans-serif;
```

波斯语字符由 `Vazirmatn` 显示，英文、拉丁缩写、数字和产品型号优先由 `Poppins` 显示。

### 5.4 绿色斜衬体例外

首页 Hero 和其他已经使用绿色衬线体的品牌强调词继续使用：

```css
font-family: "Instrument Serif", serif;
font-style: italic;
```

例外包括但不限于：

- `IT`；
- `Network`；
- `Collaboration`；
- 当前 Hero 动态切换的其他绿色强调词。

例外只适用于绿色斜衬体元素本身，不向父容器或相邻普通文字扩散。

## 6. 首页 Hero 按钮

### 6.1 尺寸

“查看解决方案”和“联系我们”必须：

- 高度均为 `48px`；
- 使用同一共享宽度；
- 使用 `28px` 水平内边距作为测量基础；
- 文字与箭头保持单行；
- 文字与箭头垂直居中；
- 两按钮间距为 `12px` 至 `16px`。

共享宽度以当前本地化“查看解决方案”按钮的自然宽度为基准。若另一语言中的“联系我们”更长，则以两者中较长者为准。

参考桌面宽度：

- 英文约 `222px`；
- 中文约 `162px`；
- 波斯语约 `165px`。

实际实现不硬编码三组文本宽度，而是由同一按钮组布局或测量逻辑得出共享宽度。

### 6.2 响应式与方向

- 两按钮总宽度可容纳时保持同一行；
- 空间不足时整颗按钮换行；
- 换行后两个按钮仍保持相同宽度；
- 按钮文字内部不得换行；
- 波斯语按钮内部文字与箭头按 RTL 镜像排列；
- 键盘焦点样式和现有悬停状态继续保留。

## 7. 卡片中轴与文字对齐

### 7.1 全生命周期服务

每张服务卡采用三层结构：

1. 居中的卡片外层；
2. 居中的图标区域；
3. 居中的文字列。

文字列要求：

- `max-inline-size: 300px`；
- `margin-inline: auto`；
- 宽度不超过卡片可用空间；
- 英文和中文使用 `text-align: left/start`；
- 波斯语使用 `text-align: right/start`；
- 标题和正文共用相同的语言起始线。

图标中心、文字列中心和卡片中心的水平偏差不得超过 `2px`。

### 7.2 项目案例

项目案例卡片沿用同一中轴规则：

- Logo 水平居中；
- 文字列最大宽度约 `300px`；
- 文字列整体居中；
- 标题和能力标签按语言起始方向对齐；
- 不强制每段文字本身居中。

Logo 中心、文字列中心和卡片中心的水平偏差不得超过 `2px`。

## 8. 核心能力提示动效

### 8.1 触发

- 观察 `#solutions` 或实际卡片滚动容器所在板块；
- 板块进入视口约 `25%` 时立即启动；
- 不再使用额外的启动延迟；
- 每次页面加载最多完整播放一次。

### 8.2 位移与时间

- 位移为相邻卡片间距的约 `42%`；
- 最大位移为 `180px`；
- LTR 向后续卡片方向移动；
- RTL 使用镜像方向；
- 前进时间约 `700ms`；
- 停留约 `500ms`；
- 返回时间约 `650ms`；
- 返回后恢复原有 `scroll-snap`。

### 8.3 取消与降级

以下操作会取消未完成的提示：

- 指针按下；
- 触摸；
- 滚轮；
- 键盘；
- 点击上一张或下一张按钮。

取消后不得强制把用户滚动位置拉回起点。

当 `prefers-reduced-motion: reduce` 生效时：

- 不播放自动提示；
- 卡片按钮继续可用；
- 逐卡导航使用即时滚动；
- 页面不得出现布局跳动。

## 11. 实现架构

### 11.1 字体与字号

新增一个只负责全站字体和字号映射的样式文件：

- `assets/site-typography-system.css`

该文件包含：

- 全站字体栈；
- 文字 token；
- 对现有页面结构的 selector 映射；
- 响应式规则；
- Poppins 例外规则；
- 正常文字最小字号约束。

避免继续把所有覆盖追加到已经压缩的主 CSS 文件中。

### 11.2 Mall 导航和占位页

新增一个只负责 Mall 的增强模块：

- `assets/mall-navigation-and-page.js`

职责：

- 根据 URL 推导语言；
- 在桌面导航和移动菜单中插入本地化 Mall；
- 保证重复运行时不产生重复链接；
- 在 Mall 路由中渲染本地化占位内容；
- 在 React 首次渲染完成后写入 Mall 的 title、description、robots、canonical、Open Graph 和 hreflang，覆盖临时 Not Found 元数据；
- 保持现有共享页头和页脚；
- 处理 React 后续渲染或移动菜单延迟挂载。

增强模块使用 MutationObserver 只观察必要的导航挂载阶段，完成插入后及时断开或进入低成本幂等检查。

### 11.3 首页细节

继续扩展现有文件：

- 动效在 LTR 和 RTL 中方向正确；
- 用户交互可取消；
- 减少动效模式不自动播放；
- Mall 在桌面导航和移动菜单中位于 Blog 后；
- Mall 页面内容与语言正确；
- 所有页面无横向溢出；
- 控制台 0 error、0 warning。

## 13. 无障碍与降级

- Mall 使用真实 `<a>` 链接；
- 当前 Mall 页面在导航中使用 `aria-current="page"`；
- 移动菜单中的 Mall 可通过键盘聚焦；
- 字号调整不得破坏浏览器缩放；
- 文字不得通过固定高度截断；
- Hero 按钮使用清晰的 `:focus-visible`；
- 波斯语页面保持 `dir="rtl"`；
- 核心能力动效遵循减少动态效果偏好；
- JavaScript 增强失败时，现有内容和横向滚动仍可用；
- Mall 增强模块失败时，已有正式页面内容不受影响。
