# Solution 页面装饰编号清理与页脚统一设计

**日期：** 2026-08-05  
**状态：** 已获用户方向确认，待实施  
**适用范围：** 英文、简体中文和波斯语全部 Solution 分类页与合作伙伴详情页

## 1. 目标

清理 Solution 页面中不承载业务含义的章节序号与卡片编号，并将合作伙伴详情页的简化页脚统一为首页正在使用的完整页脚。修改后，页面保留原有内容层级、品牌风格和交互，只减少无意义视觉噪声并统一全站导航出口。

## 2. 范围

本次覆盖三种语言下全部 Solution 路由，共 75 个页面壳：

- 英文：`/solutions/**`；
- 简体中文：`/zh/solutions/**`；
- 波斯语：`/fa/solutions/**`；
- 页面类型包括 Solution 分类页和合作伙伴 Solution 详情页。

三种语言使用同一套结构规则；波斯语继续保持现有 RTL 布局。

## 3. 已确认的界面规则

### 3.1 Solution 分类页

- 保留本地化的章节文字，例如 `[ Overview ]`；
- 删除章节文字后面的装饰序号，例如 `/ 01`；
- 不改分类页的标题、正文、卡片、链接或完整首页页脚。

### 3.2 合作伙伴 Solution 详情页

- Hero 区删除 `01 / 05` 一类装饰进度编号；保留其余品牌、标题、正文、按钮和分隔线；
- “合作关系”“服务”“案例”等章节标题保留本地化文字，删除 `02`、`03`、`04` 等章节序号；
- 关系、服务与案例卡片删除 `01`、`02` 等纯排序编号；卡片标题、正文和业务信息保持不变；
- 联系区保留“开始项目”等本地化文字，删除前缀 `05 /`；
- 页面末尾改用与首页相同的完整共享页脚，替换当前只包含合作伙伴名称和邮箱的简化页脚。

### 3.3 必须保留的数字

仅删除明确属于装饰排序系统的数字节点。以下内容不得因本次转换受到影响：

- 年份，例如 `2010`；
- 产品型号、端口数量、容量、速率和其他技术规格；
- 公司、项目、服务或案例正文中的业务数字；
- URL、联系方式和其他具有实际信息含义的数字。

## 4. 实现方案

采用“确定性构建后转换”方案，在当前静态 React 构建产物的集成流程中完成修改。

### 4.1 转换方式

- 从 Solution 路由页面引用关系解析当前生效的 JavaScript bundle，不硬编码将来可能变化的文件名；
- 针对当前组件结构使用精确、可计数的代码锚点执行转换；
- 分类页只改写章节标签的生成表达式，使其输出本地化文字而不输出序号；
- 合作伙伴详情页移除 Hero、章节、卡片和联系区中的装饰编号节点；
- 合作伙伴详情页末尾直接复用现有首页完整页脚组件 `qn`；
- 转换脚本可重复运行：目标已处于完成状态时不重复改写，也不生成叠加内容。

### 4.2 失败保护

转换必须采用 fail-closed 策略：

- 修改前校验预期锚点与匹配数量；
- 匹配缺失、数量异常或同时出现新旧结构时立即退出并报告，不写入半完成产物；
- 写入后再次验证旧装饰结构已消失、共享页脚调用已出现；
- 不使用宽泛的数字正则，以避免误删业务与技术数字。

### 4.3 为什么不采用其他方案

#### 方案 A：只用 CSS 隐藏

- 优点：改动快。
- 缺点：数字仍存在于 DOM 和辅助技术读取路径中，也无法解决页脚复用；不采用。

#### 方案 B：运行时 DOM 修补

- 优点：无需改写现有 bundle 结构。
- 缺点：可能产生首屏闪烁、观察器开销和结构时序问题；不采用。

#### 方案 C：确定性构建后转换（采用）

- 优点：输出在浏览器加载前已经正确，无闪烁；可用严格断言覆盖当前静态架构；与现有项目集成脚本方式一致。
- 代价：上游 bundle 结构改变时脚本会主动失败，需要同步更新锚点。这是有意的安全行为。

## 5. 页脚统一

合作伙伴详情页不复制一份新的页脚 HTML，而是调用首页与分类页已经使用的共享页脚组件 `qn`。因此：

- 导航分组、联系方式、品牌文字与首页保持一致；
- 英文、中文、波斯语继续由现有本地化数据驱动；
- RTL 排版沿用共享组件既有行为；
- 每个页面只保留一个页脚 landmark，不保留旧简化页脚的残余节点。

## 6. 无障碍与响应式

- 装饰编号从实际输出结构中移除，而不是通过 `display: none` 隐藏；
- 章节标题的语义层级、按钮名称和链接目标不变；
- 删除编号后不保留无意义的空容器或多余间距；
- 桌面端、平板端和手机端沿用当前响应式布局；
- 波斯语页面继续保持 RTL 阅读顺序，不因移除编号而改变内容顺序。

## 7. 验证范围

### 7.1 静态合约验证

- 75 个 Solution 路由页面壳仍引用同一个当前生效 bundle；
- 分类页不再生成 `/ 01` 一类章节序号，但仍生成本地化章节文字；
- 合作伙伴详情页不再包含 Hero、章节、卡片和联系区的装饰编号实现；
- 合作伙伴详情页使用共享完整页脚，旧简化页脚结构不存在；
- `2010` 等已知业务数字仍存在，且转换规则不匹配型号或技术规格；
- 集成脚本重复运行不会产生第二次修改。

### 7.2 浏览器验证

使用 Playwright 覆盖英文、中文和波斯语：

- 每种语言至少检查一个 Solution 分类页和 Cisco 合作伙伴详情页；
- 桌面视口 `1440 × 900` 与手机视口 `390 × 844`；
- 页面可正常加载，Hero 与各章节没有装饰序号；
- 有意义的数字内容仍可见；
- 合作伙伴详情页页脚内容与对应语言首页一致，页面仅有一个页脚；
- 波斯语 RTL 方向正确；
- 页面无横向溢出，控制台无新增错误或警告。

## 8. 非目标

- 不删除首页、Blog、Mall 或其他非 Solution 页面的编号；
- 不改 Solution 页面的文案、图片、按钮、卡片内容或整体视觉布局；
- 不删除任何业务或技术数字；
- 不重构整个静态 React bundle 或迁移技术栈；
- 本设计文档提交不包含线上部署。代码实施完成后的发布仍需遵循项目既有发布流程和用户授权。
