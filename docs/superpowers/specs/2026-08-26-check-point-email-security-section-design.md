# Check Point 邮件与协作安全版面设计

**日期：** 2026-08-26

**适用页面：** Check Point 中文、英文和波斯语合作伙伴详情页

**状态：** 版面方向已确认

## 1. 目标

在现有 `Security → Check Point` 详情页内增加一个独立的 **Harmony Email & Collaboration 邮件与协作安全** 版面，让客户能够快速理解产品价值、核心防护能力、平台覆盖与合规信息，并自然进入 JOTO 服务和咨询转化。

本次不新增与 Security、Networking 等并列的顶级 Solution 类型，也不建立独立邮件安全子页面。

## 2. 已确认的页面位置

新版面位于 Check Point 详情页的产品总体优势区与 JOTO 服务区之间：

1. Check Point Hero 与总体价值主张；
2. 统一策略连接网络、云、用户和终端的现有优势区；
3. **Harmony Email & Collaboration 邮件与协作安全新版面；**
4. JOTO Check Point 架构、集成、策略治理与持续运营服务；
5. 联系咨询表单与页脚。

该顺序建立“认识 Check Point → 理解邮件安全重点方案 → 了解 JOTO 交付能力 → 提交咨询”的阅读路径。

## 3. 内容架构

### 3.1 标题与价值主张

- 产品标识：`Harmony Email & Collaboration`；
- 主标题：“AI 驱动的邮件与协作安全”；
- 核心文案：强调在威胁进入收件箱前拦截网络钓鱼、商业邮件泄露（BEC）、恶意文件、恶意二维码和账户接管，并保护协作应用中的敏感数据。

### 3.2 核心能力

以四张等权能力卡呈现：

1. **高级钓鱼与 BEC 防护**：结合发件身份、语义、行为与威胁情报判定精准攻击；
2. **账户接管检测**：根据用户行为基线识别异常登录、邮件规则和发送模式；
3. **API Inline 部署**：强调不修改 MX 记录与 Microsoft 365、Gmail 快速集成；
4. **DLP 与协作防护**：覆盖邮件、文件分享与协作应用中的敏感数据可视与控制。

### 3.3 平台覆盖与合规

- 平台标签：Microsoft 365、Gmail、Teams、Slack、OneDrive、SharePoint 和 Google Drive；
- 合规标签：SOC 2 Type 2、ISO 27001、GDPR 和 HIPAA；
- 合规信息只作为支撑信号，不在页面中展开数据架构、密钥轮换、备份恢复或子处理者等技术细节。

### 3.4 行动入口

- 主 CTA：“咨询邮件安全方案”，定位到页面现有联系表单；
- 次 CTA：“了解 JOTO 交付能力”，定位到紧随其后的 JOTO Check Point 服务区；
- 不新增外部试用、报告下载或第三方表单链接。

## 4. 视觉设计

页面继续使用 JOTO Solution 详情页现有的深色安全视觉，不整页复制 Check Point 官网样式。新版面使用局部 Check Point 洋红色作为产品识别：

- 背景保持深黑与深绿主调；
- 主标题关键词、产品标识、重要边框和主 CTA 使用洋红色；
- 首屏右侧使用一个“邮件威胁已拦截”抽象界面，不复制 Check Point 产品控制台；
- 桌面端为左文案、右视觉的双栏布局；
- 手机端转为单列，价值主张、CTA、视觉和能力卡按阅读顺序堆叠；
- 间距、容器宽度、字体、圆角和断点继承现有详情页规则。

## 5. 多语言与可访问性

- 英文、简体中文和波斯语页面使用同一内容结构；
- 波斯语使用逻辑方向属性，双栏顺序、文字对齐与 CTA 排列适配 RTL；
- 所有标题、正文、按钮和状态信息使用真实文本，不把文字嵌入图片；
- 洋红色不作为唯一状态区分方式，文字和边框同时传达信息；
- CTA 支持键盘聚焦，页内定位后不被固定页头遮挡。

## 6. 内容来源与限制

页面文案基于以下参考资料进行编辑性改写：

- Check Point Harmony Email Security 官方产品页；
- `10-CN_2025_HEC_v2(1).pptx`；
- `Check Point Email Security Certifications.pdf`；
- `Check Point Email Security - 数据处理说明 20260427-zh-CN.pdf`。

官方资料中的客户数量、防护率、分析机构评级、市场领导者表述和带日期的统计数据可能变化，本版面不展示这些时效性数字，避免后续维护风险。

## 7. 技术边界

- 优先扩展现有合作伙伴详情页数据和共享渲染结构，不在三语 HTML 中手工复制三份完整版面；
- 邮件安全版面只在 Check Point 详情页渲染，不影响 Fortinet、Palo Alto Networks 等其他安全合作伙页面；
- 保留现有联系表单提交逻辑，新 CTA 只触发页内定位；
- 不修改网站主导航、Solution 分类、URL 结构、SEO 路由或后端 API；
- 不直接引入官网截图、客户 Logo、Gartner 图表或未授权第三方视觉。

## 8. 失败与降级行为

- 新版面视觉资源加载失败时，标题、正文、能力卡与 CTA 仍可阅读和使用；
- 页内定位失败时，CTA 不应跳转到错误页；
- 新版面渲染条件失败时，原 Check Point 详情页其余内容保持完整。

## 9. 验证与验收标准

### 9.1 静态验证

- Check Point 三语页面都具有邮件安全本地化文案；
- 其他合作伙页面不渲染该版面；
- 主 CTA 和次 CTA 的页内目标存在；
- 不增加新顶级 Solution 类型或子路由。

### 9.2 浏览器验证

在中文、英文和波斯语 Check Point 页面验证桌面和手机视口：

- 版面位于总体优势区与 JOTO 服务区之间；
- 无文字裁切、卡片重叠、横向溢出或意外换行；
- 波斯语 RTL 阅读顺序、对齐和按钮排列正确；
- 主 CTA 滚动到联系表单，次 CTA 滚动到 JOTO 服务区；
- 页面没有新的控制台错误和资源加载错误；
- 现有 Hero、优势区、JOTO 服务、联系表单和页脚无回归。

## 10. 明确不在范围内

- 新增邮件安全独立 URL 或 SEO 落地页；
- 修改网站一级、二级 Solution 分类；
- 上传或对外公开数据处理说明、认证 PDF 和销售 PPTX；
- 新增试用申请、产品定价、下载中心或外部跳转流程；
- 复制 Check Point 官网完整内容、客户案例、市场排名或时效性统计。
