# 商城列表、语言入口与滚动驱动解决方案板块设计

**日期：** 2026-08-02  
**状态：** 已获用户方向确认，待实施  
**适用范围：** 英文、简体中文和波斯语站点；商城首页/产品列表；三语言首页的 `What we deliver` / “核心能力”解决方案板块；所有共用页头

## 1. 目标

本次更新同时解决四组已确认问题：

1. 商城列表模式与网格模式共用完全相同的筛选结果和分页，每页均为 24 件产品；
2. 商城列表模式显著压缩行高，提高单屏产品密度，并明确显示当前分类名称；
3. 公开语言菜单只保留英文和中文，波斯语通过浏览器语言自动识别，同时保持 `/fa/` 路由可直接访问；
4. 手机菜单补齐 Mall 入口；桌面端首页解决方案板块升级为纵向滚动驱动的横向展示。

## 2. 已确认的产品行为

### 2.1 商城筛选与数量

- 网格和列表只改变呈现方式，不改变产品集合、当前分类、搜索词、页码规则或排序。
- 两种视图统一使用 `24` 件/页。
- 切换视图时保留搜索词和分类，页码回到第 1 页。
- 当前数据共 229 件，其中首层分类数量为：
  - Routers：117；
  - Switches：100；
  - Firewalls：10；
  - Storages：2。
- 因此选中 `Storages` 时显示 2 件是正确结果，不应自动清除筛选。
- 结果标题必须反映当前状态：
  - 未筛选：`All products · 229 products` / `全部产品 · 229 件产品`；
  - 分类筛选：`Storages · 2 products`；
  - 波斯语使用对应本地化数量文案，技术分类名保持英文。

### 2.2 列表密度

桌面端（`>= 1024px`）：

- 单行目标高度约 `76px`，允许边框造成 1–2px 视觉差；
- 图片列宽约 `92px`，图片继续使用 `object-fit: contain`；
- 文字区采用单行横向信息结构：品牌 + 型号 / 产品类型 / 查看详情；
- 品牌、型号和产品类型均不得挤压“查看详情”；
- 型号保持单行，超长时使用省略号，但完整值继续存在于链接的无障碍名称或 `title` 中；
- 行间距控制在 `6–8px`，不再使用网格卡片的纵向留白。

平板和手机：

- 列表仍保持高密度，目标高度约 `88px`；
- 图片列约 `88–96px`；
- 隐藏次要产品类型，只保留品牌、型号和查看详情；
- 不产生横向页面溢出。

## 3. 语言入口策略

### 3.1 公开菜单

- 英文和中文页面的语言菜单只显示：
  - `EN`；
  - `中文`。
- 不显示 `فارسی`，避免将波斯语入口直接暴露在公开切换菜单中。
- 波斯语页面本身也不把波斯语作为可选菜单项；当前语言按钮可显示页面当前语言，但展开后的可切换目标仅为英文和中文。

### 3.2 自动识别

- 不使用 IP 地址、不接入第三方地理定位服务。
- 当浏览器首选语言列表包含 `fa` 或以 `fa-` 开头的语言代码时，从无语言前缀入口自动转入对应 `/fa/` 路由。
- 已有 `/fa/` 路由、页面内容、RTL 布局、SEO alternate 和直接链接继续保留。
- 用户显式访问 `/zh/`、`/fa/` 或其他带语言前缀的 URL 时，以 URL 为准。
- 用户选择英文或中文后，继续使用现有 `joto:locale` 本地存储记住选择，避免每次访问被浏览器语言反复覆盖。

## 4. 手机端 Mall 导航

### 4.1 问题原因

Mall 链接由共享增强脚本在 Blog / 最新资讯链接后动态克隆。手机菜单属于延迟挂载内容，而当前 DOM 监听在 15 秒后停止，因此较晚打开手机菜单时不会获得 Mall 链接。

### 4.2 修正原则

- 桌面和手机菜单都在 Blog / 最新资讯之后插入 Mall；
- 英文显示 `Mall`，中文显示 `商城`，波斯语页面显示 `فروشگاه`；
- 链接分别指向 `/mall/`、`/zh/mall/`、`/fa/mall/`；
- 监听逻辑必须幂等，菜单重复打开或 React 重新挂载时不得产生重复链接；
- 使用轻量的 `MutationObserver` + `requestAnimationFrame` 合并更新，不因持续观察造成频繁同步布局；
- Mall 页面正确设置 `aria-current="page"`。

## 5. 滚动驱动的解决方案横向板块

### 5.1 适用范围

- 英文、中文和波斯语首页；
- 仅在视口宽度 `>= 1024px`、浏览器支持必要布局能力、且用户未开启减少动态效果时启用；
- 手机及较窄平板继续使用原生横向滑动和左右按钮，不锁定纵向浏览。

### 5.2 交互模型

采用“纵向滚动区间 + 内部粘性舞台 + 横向位移映射”，不直接阻止滚轮默认行为：

1. 页面正常滚动进入解决方案板块；
2. 板块舞台到达页头下方后使用 `position: sticky` 保持在视口；
3. 用户继续纵向滚动，外层滚动进度从 `0` 到 `1`；
4. 进度映射到卡片轨道从起点到终点的横向 `translate3d`；
5. 最后一张卡片完整进入视口后，粘性区段自然结束，页面继续向下；
6. 反向滚动时按同一进度自然回放。

该方案不使用 `wheel.preventDefault()`，避免触控板卡顿、惯性中断和键盘/触摸滚动异常。

### 5.3 滚动距离和布局

- 外层区段的额外纵向距离根据横向可滚动距离动态计算，而不是写死固定像素；
- 粘性舞台顶部避开站点固定页头；
- 舞台高度应容纳标题、说明、控制按钮、卡片和 CTA，但不强制使用完整 `100vh`，避免小高度桌面裁切；
- 最后一张卡片在终点必须完整可见；
- 视口或字体变化时重新测量，使用 `ResizeObserver` 合并更新。

### 5.4 性能

- 滚动监听使用被动监听，不拦截默认行为；
- 每帧最多执行一次读写，统一进入 `requestAnimationFrame`；
- 位移使用 `transform: translate3d()`，不在滚动过程中反复设置 `scrollLeft`；
- 测量阶段和写入阶段分离，避免布局抖动；
- 卡片图片不增加新的缩放或模糊动画；
- 离开区段后不继续执行不必要的视觉写入。

### 5.5 方向与按钮

- 英文、中文从第一张向后推进；
- 波斯语根据 RTL 视觉顺序反向计算轨道终点；
- 左右按钮不直接制造与页面进度冲突：点击按钮时，将页面滚动位置移动到对应卡片的纵向进度；
- 当前卡片和首尾禁用状态继续同步。

### 5.6 无障碍与降级

- `prefers-reduced-motion: reduce`：不启用粘性横向映射，保留普通板块、原生横向滑动和按钮；
- `<= 1023px`：不启用纵向驱动，保持触摸滑动；
- 键盘 Tab 顺序仍按照 DOM 卡片顺序；
- 页面刷新或通过锚点进入时，根据当前滚动位置正确恢复进度；
- JavaScript 失败时，卡片仍可通过原生横向滚动访问。

## 6. 方案对比

### 方案 A：粘性舞台 + 滚动进度映射（采用）

- 优点：视觉符合要求；不劫持滚轮；支持触控板惯性、反向滚动和浏览器原生滚动；性能可控。
- 代价：需要精确测量轨道宽度和外层纵向距离。

### 方案 B：监听滚轮并阻止默认纵向滚动

- 优点：逻辑直观。
- 缺点：容易产生卡顿、滚动锁死、触控板惯性异常和无障碍问题；不采用。

### 方案 C：引入 GSAP ScrollTrigger

- 优点：成熟的时间线和固定区段控制。
- 缺点：增加第三方依赖和发布体积，现有需求不需要；不采用。

## 7. 验证范围

### 7.1 静态验证

- 网格和列表使用同一 `pageSize: 24`；
- 结果标题读取当前分类；
- 语言菜单可见选项不含波斯语；
- `fa` 浏览器语言自动路由逻辑仍存在；
- 手机菜单动态挂载后出现且只出现一个 Mall 链接；
- 横向滚动实现不含 `wheel.preventDefault()`；
- 减少动态效果和窄屏降级规则存在。

### 7.2 浏览器验证

覆盖英文、中文、波斯语：

- `1440 × 900`：网格/列表切换、24 件分页、分类数量、76px 左右列表行、滚动驱动完整起止、按钮同步；
- `1024 × 768`：粘性舞台完整可见且无裁切；
- `390 × 844`：手机菜单 Mall 可见、商城无横向溢出、列表密度合理、解决方案仍为原生触摸滑动；
- 波斯语：RTL 方向正确，菜单不暴露波斯语选项，自动路由可通过浏览器语言模拟；
- 减少动态效果：解决方案板块不固定、不自动位移；
- 控制台无错误和警告。

## 8. 非目标

- 不删除波斯语页面或 `/fa/` 路由；
- 不使用访客 IP 或第三方定位；
- 不改变产品抓取数据、分类归属或产品详情内容；
- 不改变网格卡片密度；
- 不在手机端启用纵向滚动锁定；
- 本设计阶段不直接发布线上版本，发布需在实现、回归和提交完成后按用户后续指令执行。
