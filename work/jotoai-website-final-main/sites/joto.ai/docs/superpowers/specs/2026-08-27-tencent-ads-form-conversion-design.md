# joto.ai 腾讯广告表单转化追踪设计

## 目标

为 `joto.ai` 接入腾讯广告网页转化追踪。仅当联系表单请求被 `https://admin.jotoai.com/api/contact` 成功接收时，上报一次“表单预约”转化；按钮点击、验证码错误、字段错误和接口失败均不得计为转化。

腾讯广告账户 `88991166` 已创建网页转化规则：

- 名称：`joto.ai_官网需求表单提交`
- 转化 ID：`88832221`
- 上报方式：JS（可视化埋点）
- 优化目标：表单预约
- 归因方式：点击归因

## 现状

- 全站布局位于 `app/layout.tsx`，现有统计入口为 `components/Analytics.tsx`。
- 联系表单位于 `components/sections/PocForm.tsx`。
- 表单提交成功后已经上报百度虚拟页面浏览、百度事件和 GA4 `generate_lead`。
- 现有分析事件均放在后端接口返回成功的分支中，并且埋点异常不会影响表单业务流程。

## 方案选择

采用“全站基础脚本 + 成功分支代码上报”。不采用可视化圈选提交按钮，因为按钮点击可能对应验证码错误或接口失败；不依赖动态成功提示的可视化选择器，因为页面结构调整可能使选择器失效。

## 设计

### 基础脚本

在现有 `Analytics` 组件中增加腾讯广告 SDK 初始化。数据源 ID 通过公开环境变量提供，变量未配置时不渲染任何腾讯脚本：

```text
NEXT_PUBLIC_TENCENT_ADS_ACTION_SET_ID
```

基础脚本加载后初始化该数据源，并上报 `PAGE_VIEW`。数据源 ID 本身会出现在前端页面源码中，不作为服务端密钥使用。

### 转化事件

封装一个小型客户端函数，用于在 SDK 可用时上报腾讯“表单预约”事件。`PocForm` 只在 `/api/contact` 返回成功、表单重置之后调用该函数。

约束：

- 接口失败时不上报。
- 同一次成功提交只调用一次。
- SDK 未加载、加载失败或上报抛错时静默跳过，不改变表单成功状态。
- 不向腾讯发送姓名、企业、邮箱、手机号、微信号、问题描述或验证码等表单内容。

腾讯 JS SDK 的行为常量使用 `RESERVATION`，与本规则的“表单预约”优化目标对应。调用形式为 `gdt("track", "RESERVATION")`，不附加表单字段或其他用户数据。

### 数据流

```text
用户提交表单
→ admin.jotoai.com 校验验证码并接收线索
→ 接口返回成功
→ 页面显示提交成功
→ 百度 / GA4 / 腾讯广告分别上报转化事件
```

腾讯广告只收到事件类型及浏览器侧归因信息，不接收表单字段。

### 配置与发布

- 本地和无变量环境保持当前行为。
- 生产环境配置 `NEXT_PUBLIC_TENCENT_ADS_ACTION_SET_ID` 后重新构建部署。
- 本任务不自动发布生产环境；发布沿用项目既有流程。

## 验证

增加与现有测试风格一致的最小回归测试，确认：

1. 全站分析入口按环境变量注入腾讯 SDK。
2. 表单成功分支包含腾讯事件调用。
3. 错误分支不包含腾讯转化调用。
4. SDK 不存在或上报异常时不会影响表单成功结果。

完成部署后，在腾讯广告后台对转化 ID `88832221` 执行“转化联调”，通过广告测试链路提交一条明确标记的测试需求，验证平台收到一次“表单预约”。测试数据的清理由站点后台按正常测试线索流程处理。

## 非目标

- 不启用深度优化目标或 ROI 上报。
- 不追踪电话、邮件、微信二维码等其他联系行为。
- 不修改表单字段、验证码、后台接口或线索通知流程。
- 不在本次任务中创建、调整或启动腾讯广告营销单元。
